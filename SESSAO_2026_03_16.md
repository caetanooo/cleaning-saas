# Sessão de Desenvolvimento — 2026-03-16

## Contexto

Implementação do sistema de **Agendamento Dinâmico** baseado no `IMPLEMENTATION_PLAN_AGENDA.md` e no `PRD_CLEANER_AGENDA.md`.
O sistema anterior usava turnos fixos (Manhã/Tarde). O novo modelo calcula horários disponíveis com base na duração estimada do serviço e no tamanho da equipe.

### 4. Lógica de Cálculo (`lib/timeCalculator.ts`)
Funções puras sem side effects:

| Função | Descrição |
|---|---|
| `calculateDuration(input)` | Equação: `(T_base + Σ rooms × T_room) / N_staff`, retorna `null` se sem configs |
| `hasOverlap(start, duration, blocks)` | Detecta sobreposição com buffer de 45 min em cada lado |
| `getAvailableSlots(duration, blocks, workStart, workEnd, nowMin)` | Gera array de slots disponíveis a cada 30 min |
| `bookingRowsToBlocks(rows)` | Converte rows do DB (legacy `time_block` ou `scheduled_start_at`) para `{startMin, endMin}` |
| `legacyBlockToMinutes(timeBlock)` | Manhã → `{540, 780}`, Tarde → `{810, 1080}` |
| `minutesToTime(min)` / `timeToMinutes(hhmm)` | Conversores de formato |

Constantes exportadas: `TRAVEL_TIME_MINUTES = 45`, `SLOT_STEP_MINUTES = 30`

### Integração WhatsApp (dependência externa)

O fluxo de confirmação de equipe via WhatsApp está implementado no backend mas **inativo** por padrão.

Para ativar:
1. Criar app no [Meta Developer Portal](https://developers.facebook.com) com WhatsApp Business API
2. Adicionar ao `.env.local`:
   ```env
   WHATSAPP_VERIFY_TOKEN=...
   WHATSAPP_APP_SECRET=...
   WHATSAPP_API_TOKEN=...
   WHATSAPP_PHONE_NUMBER_ID=...
   ```
3. Registrar webhook: `https://seu-dominio.com/api/webhooks/whatsapp`
4. Implementar o envio da mensagem para a faxineira após o booking ser criado (hoje o webhook só *recebe*, não *envia*)
5. Mudar o status inicial de `"confirmed"` para `"pending"` em `app/api/bookings/route.ts` linha 203 quando o fluxo estiver pronto
